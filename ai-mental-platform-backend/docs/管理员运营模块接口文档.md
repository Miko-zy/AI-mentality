# 管理员运营模块 - 后端接口文档

> 模块范围：RBAC权限管理、普通用户账号管理、内容审核、安全危机事件管理、用户反馈处理、系统公告管理。
> 全部接口位于 `/api` 上下文下，**全部要求管理员角色**（方法级 `@PreAuthorize("hasRole('admin')")`）。
> 统一返回 `Result{code, message, data}`：**成功 code=200**；业务/参数错误 HTTP 200 + body code=400/404/500；未登录 HTTP 401；无权限 HTTP 403。

## 一、数据库变更（幂等脚本 `admin_module_db.sql`）

| 变更 | 说明 |
|---|---|
| 新建 `sys_role` | 角色表：role_code 唯一、status 0停用/1启用、逻辑删除 |
| 新建 `sys_permission` | 权限字典表：perm_code 唯一、perm_type 1菜单/2按钮、逻辑删除 |
| 新建 `sys_role_permission` | 角色权限关联表：uk(role_id,perm_id)、逻辑删除标记 |
| 新建 `content_audit_record` | 内容审核记录表：每次审核留痕一条，FK→chat_message |
| `crisis_record` 加列 | `handle_remark VARCHAR(500)` 处理备注、`handle_time DATETIME` 处理时间 |
| 种子数据 | 2 角色（super_admin 超级管理员、operator 运营专员）+ 15 权限点（user×2、audit×3、crisis×2、feedback×2、notice×4、rbac×2） |

**唯一键与逻辑删除的冲突处理**（关联表/编码唯一键）：
- `sys_role_permission` 增删分配采用**物理删除**（Mapper `@Delete` 自定义SQL），否则逻辑删除残留行占用 `uk_role_perm`，重新分配同一权限时主键冲突。
- 角色/权限新增前**物理清理同编码逻辑删除残留行**（`physicalDeleteByRoleCode/PermCode`），避免唯一键冲突。
- 删除角色/权限时级联物理清理关联分配。

## 三、接口清单（共 23 个）

### 1. RBAC 角色管理 `/admin/roles`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/roles` | 查询全部角色（RoleVO列表） |
| POST | `/admin/roles` | 新增角色 `{roleCode必填≤50唯一, roleName必填≤50, description≤255, status 0/1缺省1}` |
| PUT | `/admin/roles/{roleId}` | 编辑角色 `{roleName必填, description, status}`（**roleCode 不可改**，dto中忽略） |
| DELETE | `/admin/roles/{roleId}` | 删除角色（逻辑删 + 级联物理清权限分配；**`super_admin` 内置角色拒绝删除→400**） |
| GET | `/admin/roles/{roleId}/permissions` | 查询角色已分配权限（PermissionVO列表） |
| PUT | `/admin/roles/{roleId}/permissions` | 分配权限 `{permIds:[...]}` **全量覆盖**（传空数组=清空；permIds须全部真实存在否则400） |

错误：编码重复/内置角色删除/权限不存在 → 400；角色不存在 → 404；参数空/超长/状态非法 → 400。

### 2. RBAC 权限字典 `/admin/permissions`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/permissions` | 查询全部权限字典 |
| POST | `/admin/permissions` | 新增权限 `{permCode必填≤100唯一, permName必填≤100, permType 1菜单/2按钮缺省1, description≤255}` |
| PUT | `/admin/permissions/{permId}` | 编辑权限（**permCode 不可改**） |
| DELETE | `/admin/permissions/{permId}` | 删除权限（逻辑删 + 级联物理清角色分配） |

### 3. 普通用户账号管理 `/admin/users`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/users` | 分页查询用户。参数：`pageNum=1`、`pageSize=10`、`keyword`（昵称模糊 或 邮箱精确——邮箱AES密文存储，业务层先加密关键字再匹配）、`accountStatus` 0/1 可选。返回 `PageVO<AdminUserVO>`（email/phone 已AES解密） |
| PUT | `/admin/users/{userId}/status` | 启用/禁用账号 `{accountStatus: 0禁用/1正常}`。**禁用时同步删除 Redis `login:token:user:{userId}`，在线用户JWT立即失效** |

错误：状态取值非0/1 → 400；用户不存在 → 404。

### 4. 内容审核 `/admin/audit`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/audit/messages` | 分页查询对话消息。参数：`pageNum/pageSize`、`auditStatus` 0待审/1通过/2不通过 可选。批量补全会话归属 `userId`，消息内容AES解密 |
| POST | `/admin/audit/messages/{msgId}` | 审核消息 `{auditResult: 1通过/2不通过必填, violateFlag 0/1可选缺省由结果推导(不通过→1), auditRemark≤500可选}`。**同时**：更新 `chat_message.audit_status/violate_flag` + 插入 `content_audit_record` 留痕（允许重复审核，历史保留）。返回 `AuditRecordVO`（含 auditorName、msgContent） |
| GET | `/admin/audit/records` | 分页查询审核记录。参数：`pageNum/pageSize`、`msgId` 可选筛选。批量补全被审消息内容/发送时间、审核人账号 |

错误：auditResult 非1/2、备注超长 → 400；消息不存在 → 404。

### 5. 安全危机事件 `/admin/crisis`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/crisis` | 分页查询危机事件。参数：`pageNum/pageSize`、`handleStatus` 0待处理/1已处理 可选。批量补全用户昵称、关联风险消息内容（AES解密） |
| PUT | `/admin/crisis/{crisisId}` | 处理事件 `{handleStatus: 0/1必填, handleRemark≤500可选}`。更新状态与备注（未传备注保留原值），刷新 `handle_time` |

错误：状态非0/1、备注超长 → 400；事件不存在 → 404。

### 6. 用户反馈处理 `/admin/feedback`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/feedback` | 分页查询反馈。参数：`pageNum/pageSize`、`status` 0待处理/1已回复/2关闭 可选。批量补全反馈用户昵称（`AdminFeedbackVO`） |
| PUT | `/admin/feedback/{feedbackId}` | 处理反馈 `{status: 0/1/2必填, replyContent≤1000}`。**status=1 时 replyContent 必填**；未传 replyContent 保留原回复；更新 `update_time` |

错误：状态非法、已回复未填回复、回复超长 → 400；反馈不存在 → 404。

### 7. 系统公告 `/admin/notices`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/notices` | 查询全部公告（倒序）。批量补全发布管理员账号 `adminName` |
| POST | `/admin/notices` | 新增公告 `{noticeTitle必填≤100, noticeContent必填≤5000, status 0草稿/1已发布/2下架 缺省0}`。status=1 时记录 `publish_time=now` + `admin_id=当前管理员` |
| PUT | `/admin/notices/{noticeId}` | 编辑公告（**仅改标题正文，不改状态**；title/content 均必填） |
| PUT | `/admin/notices/{noticeId}/status` | 修改状态 `{status: 0/1/2}`（**发布/停用走此接口**；置1时刷新 `publish_time` 与发布人） |

错误：标题/正文空或超长、状态非0/1/2 → 400；公告不存在 → 404。
